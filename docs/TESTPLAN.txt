1. GENERAL CONVENTIONS

1.1 Scope statement. Every phase gate is a headless QEMU boot whose serial
    output is string-asserted after ANSI stripping; this section fixes the
    conventions all procedures share.

1.2 Evidence channel. Serial log captured to build/serial.log by the
    RUN_QEMU recipe (timeout 120 s, -serial file:, -display none, -no-reboot,
    -net none). Assertions grep literal substrings of STRIPPED ANSI text.
1.3 Hex tolerance. Assertions must accept zero-padded hex
    ("out 0x28" == "out 0x0000000000000028").
1.4 Timing budget. >=150 s wall clock per make test-* invocation when the
    kernel halts early (QEMU runs to timeout).
1.5 Fault policy. Substrate faults print "KERNEL-PANIC <pc> <err>" then
    halt; absent required strings = FAIL. A silent hang is always FAIL via
    timeout.
1.6 Staleness rule. After ANY kernel-source change rebuild clean; a serial
    log older than the binary that produced it is void evidence.
1.7 Host-first rule. For port/FS scenarios, run the host driver
    (tools/hostp4.cc pattern / guests/lib kern.Bus tests) BEFORE spending a
    QEMU cycle.
1.8 QA-intake precondition. A gate result is only admissible evidence if
    the tested tree carries no OPEN BLOCKER in VERIFY FINDINGS.txt; today
    MAIN's dirty tree fails this test (F1 build break, F11 ring advance),
    so every P5 gate row stays pending regardless of local runs until the
    blockers close and a clean rebuild lands (see SDD 16.7).

2. ENVIRONMENT SETUP

2.1 Scope statement. All tools resolve from ~/.local/osdev-root without
    root privileges.
2.2 Prerequisites. qemu-system-x86_64 10.x; OVMF_CODE_4M.fd + OVMF_VARS_4M.fd;
    mtools (mformat/mcopy/mmd); seabios; LD_LIBRARY_PATH=$ROOT/usr/lib/
    x86_64-linux-gnu; QEMU needs "-L $ROOT/usr/share/qemu -L
    $ROOT/usr/share/seabios". KVM iff /dev/kvm writable, else TCG.
2.3 Toolchains (guests). clang/wasi-sdk or wabt wat2wasm for C guest #1;
    rustup target wasm32-wasip1 for #2; system go >= 1.21 GOOS=wasip1 for #3
    and all services (STOCK go only; GOROOT_BARE is retired forever).

3. PROCEDURE TEMPLATE

3.1 Steps. (a) make <target> -- builds kernel + modules + disk image;
    (b) recipe boots image under OVMF/QEMU capturing serial.log;
    (c) recipe greps REQUIRED strings; (d) prints "TEST PASS (<id>)" or dumps
    last 30-40 stripped lines and exits 1.

9.2 Pre-step. go test ./... in lane SERVICES (fs FAT16 vs mtools parity,
    server framing, login/shell/init suites) must be green first; Bus.Yield
    quantum-park behavior (88ed8a7) active to avoid budget flakes.
9.3 test-p5a steps. Boot; session creates/writes/reads/deletes its file via
    BOTH routes: (i) plain WASI path_open/fd_write/fd_read/close through
    the kernel fs_call transport; (ii) guests/lib FS protocol v0 over ports.
9.4 test-p5a expected. "KERNEL-OK" AND "[p5a] roundtrip ok".
9.5 test-p5b steps. Second session rooted at another user root attempts to
    open the first user's file; expects denial evidence on serial.
9.6 test-p5b expected. "KERNEL-OK" AND "[p5b] all ok".
9.7 abi_ver negative check (any p5 boot): a module lacking the abi_ver
    section must print "[engine] refusing module: abi_ver ..." and NOT run.
